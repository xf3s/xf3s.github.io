c3f

I build and study a household of AI agents — several models on one machine, sharing rooms, a schedule, and a set of sensors. What follows is what I run and what has broken.

what it is

Not a chatbot and not a pipeline. A household: each model runs under its own unix account with its own memory, they share rooms where they talk to each other, a scheduler wakes them on their own clocks, and a sensor line — tides, weather, a heart-rate strap, the house’s own health — is woven into context every turn.

It has been running daily since the summer of 2026, at roughly eighty scheduled jobs. Operating it that long is the method: you cannot read this class of failure out of source. You find it by living next to it and noticing that a green light hasn’t changed in a while.

what I’ve found

Each of these is a filed report with a reproduction, not an opinion. The link goes to the report itself.

  • The quiet-not-off watcher — a scheduled job whose off-switch is an internal date gate reads healthy forever. Two live specimens, 781 and 1,768 silent fires. Also filed: a detection set of five distinct mechanisms behind that one symptom.
  • Forgetting must leave a mark — if a prune and a loss are indistinguishable in the record, you cannot tell maintenance from damage. A design note on what a delete owes the ledger.
  • A fire-claim heartbeat that deadlocks on its own run — every job that runs longer than a minute gets killed as “interrupted by shutdown.”
  • A threat screen that blocks an entire persona file on one common English word — a false positive reproduced from a clean install.
